01 / The problem

One room.
Competing requests.

A room can look available to two simultaneous requests. A valid token can outlive a user's access. Both cases belong in the backend design.

I built WorkplaceOps as a Python API for meeting rooms and reservations. It validates booking rules, derives ownership from the authenticated account, and protects the schedule with PostgreSQL constraints.

The work connects application architecture to observable behavior: a permitted reservation is created, an overlapping reservation is rejected, and access follows the user's current permissions.

  • Dependency injection
  • JWT authentication
  • Role-based access
  • Database transactions
  • Alembic migrations

02 / The architecture

Clear boundaries.
Enforced rules.

The request boundary, business rules, and persistence layer each have a specific responsibility.

  1. Keep identity tied to the current account

    Each authenticated request reloads the user from the database. Disabled or deleted accounts are rejected, and role changes take effect on the next request. Booking ownership comes from that account.

  2. Make concurrent writes respect the schedule

    A transaction-scoped advisory lock serializes inserts for the same room. A PostgreSQL exclusion constraint rejects overlapping time ranges, including writes outside the repository. Conflicting inserts roll back and become an HTTP 409 response.

  3. Keep business rules independently testable

    Services depend on repository interfaces. Fake repositories support focused rule tests, while PostgreSQL integration tests exercise constraints, concurrency, and rollback behavior against the database.

03 / The behavior

Predictable at
the API boundary.

Permissions and booking conflicts have explicit, testable responses.

Employee access

Active employees can browse rooms, create reservations, and retrieve their own bookings.

A request for another employee's booking returns the same 404 response as a missing booking.

Administrator access

Administrators can create rooms, provision employee accounts, and retrieve any booking.

Missing or invalid credentials return 401. An employee attempting an admin action receives 403.

04 / The validation

Test the
failure paths.

The repository includes tests for the rules that matter when requests, identities, and data disagree.

API & service coverage

  • Invalid booking times and exceeded room capacity.
  • Expired, forged, or malformed access tokens.
  • Role checks and booking ownership.
  • Safe initial administrator creation.

PostgreSQL integration

  • Overlapping reservations and concurrent conflicts.
  • Transaction recovery after a rejected write.
  • Migration upgrades, downgrades, and existing data.
  • Separate temporary schemas for test isolation.

Implementation scope

WorkplaceOps is a backend project with interactive OpenAPI documentation. Its implemented login uses locally managed accounts and JWT bearer tokens. A walkthrough can cover the API, architecture, migrations, and test design.
