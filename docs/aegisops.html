01 / The problem

Beyond an
offline score.

A deployed model needs a reproducible path from training data to predictions—and a way to investigate when that behavior changes.

AegisOps connects preprocessing, model training, threshold selection, promotion, serving, and monitoring in a single credit-risk workflow. The investigation layer turns monitoring evidence into structured diagnosis and recommended actions.

I built deterministic data preparation, Logistic Regression and XGBoost training, validation-only threshold selection, test gates, versioned promotion, a FastAPI service on Cloud Run, monitoring reports, synthetic incidents, and a routed LangGraph workflow.

03 / The decisions

Make the
boundaries explicit.

  1. Choose the threshold on validation data

    Cost-aware threshold selection is part of model development. Keeping it on validation data preserves the test set for a separate check, while making the operating decision explicit alongside the trained model.

  2. Promote a versioned artifact through test gates

    The workflow connects reproducible preprocessing, trained models, validation checks, and immutable promotion. Serving and later investigation can refer to the model metadata associated with the promoted version.

  3. Separate evidence collection from interpretation

    Loading, validation, triage, routing, and tool-based evidence collection are deterministic. Gemini interprets the collected context. The agent cannot retrain, roll back, redeploy, or modify production.
