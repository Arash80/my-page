01 / The problem

Evaluate in
the right order.

Fraud detection needs to account for time, rare events, uncertain predictions, and a changing data distribution.

Random validation and an accuracy-only summary can hide temporal leakage and minority-class failures. The platform brings data preparation, model comparison, uncertainty, serving, and monitoring into one reproducible workflow.

I connected temporal validation, LightGBM and XGBoost experiments, calibration, conformal prediction, MLflow tracking, Airflow orchestration, and API serving. A separate AWS implementation covers managed processing, training, evaluation, deployment, and endpoint inference.

03 / The decisions

Treat evaluation
as a system.

  1. Preserve the temporal structure

    Time-aware validation reflects the ordering of a deployed prediction task. It makes the evaluation boundary explicit and helps surface leakage that random partitions can conceal.

  2. Examine uncertainty alongside predictions

    Calibration and conformal prediction extend the evaluation beyond model ranking. They provide complementary ways to inspect confidence and uncertainty when deciding how predictions should be used.

  3. Connect experiments to operation

    MLflow records experiments; orchestration makes stages repeatable; the serving and monitoring components carry the workflow beyond training. Local containers and AWS components exercise different delivery contexts.

04 / The evaluation

Different questions.
Separate checks.

Each part of the evaluation answers a different operational question.

Temporal validation
How does the model behave on data that follows its training period?
Model comparison
How do the LightGBM and XGBoost experiments compare under the same workflow?
Calibration
How closely do predicted probabilities correspond to observed outcomes?
Conformal prediction
How can predictive uncertainty be represented under the method’s assumptions?
Monitoring
How does incoming data change relative to the model’s reference data?
