01 / The problem

Make the answer
inspectable.

A document assistant becomes more useful when a reader can follow an answer back to its source.

TechRAG combines PDF extraction, sentence-transformer embeddings, cosine-similarity retrieval, and an Ollama-hosted model. The browser and API interfaces share the same retrieval core, with source pages, retrieved chunks, relevance scores, and latency visible in the response.

I built the ingestion and question-answering workflow, local model integration, Streamlit and FastAPI interfaces, upload safeguards, evaluation utilities, tests, and CI.

03 / The decisions

Design for
inspection and reuse.

  1. Share the core across two interfaces

    Streamlit supports interactive exploration, while FastAPI exposes the same document-question workflow to other clients. Persistent-index and upload-based requests have distinct API paths, keeping their storage behavior clear.

  2. Expose the evidence alongside the answer

    Source names, pages, chunks, relevance scores, and latency make the retrieval process inspectable. A reader can check the context and return to the PDF before relying on a generated claim.

  3. Make upload and model boundaries configurable

    PDF signature validation, path-traversal protection, and limits on file size, document count, and page count constrain ingestion. The Ollama host and model choices are explicit configuration, with local inference as the default.

04 / The evaluation

Look at retrieval.
Check the answer.

Evaluation and development material

  • Notebooks for retrieval quality and hallucination analysis.
  • Source, page, chunk, relevance, and latency reporting.
  • Unit tests that run without Ollama or model downloads.
  • Lint and test checks through GitHub Actions.

Documented limitations

  • Text extraction does not perform OCR on image-only PDFs.
  • Dense retrieval does not currently deduplicate passages.
  • Retrieved citations do not verify every generated claim.
  • Initial model loading can increase first-request latency.

Local by configuration

Uploaded PDFs are processed in memory, and retrieved text is sent to the configured Ollama server. The default server runs locally; choosing a remote host changes that data boundary.
